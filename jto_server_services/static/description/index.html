Server Services

Every service running on the server: its URL, live up/down status, and buttons to turn it on or off

What it does

  • List of services (Server Services app, administrators only): name, clickable URL, who can reach it (public, tailnet, home network, this server only), main user/password with a copy button, and notes.
  • Status (Up / Down): whether the service's address answers. A host script tests every service every 2 minutes. If no check arrives for 10 minutes, the status goes back to Unknown.
  • Power (Running / Partly running / Stopped) and Turn on / Turn off buttons in the list and the form. They start or stop the Docker containers or systemd units listed in the Container / unit field.

How it works

Odoo runs in Docker, so it can't reach the host's containers, systemd units or Tailscale addresses itself. Two scripts in ~/odoo20/server-services-checker/ run on the host and talk to Odoo at http://127.0.0.1:8069 with a secret token:

ScriptDoesOdoo endpoints
check_services.py Tests every service's Check URL (or URL) and sends Up/Down. Runs once and exits, every 2 minutes. /server_services/checker/targets, /server_services/checker/results
service_control.py Keeps running. Every 2 seconds it picks up Turn on / Turn off requests, runs docker start|stop or sudo -n systemctl start|stop, and reports Power. /server_services/control/poll, /server_services/control/report

Clicking a button only saves the request. The page waits up to 25 seconds for service_control.py to finish, then refreshes. A request nobody picks up within 2 minutes fails with "the control agent didn't answer: is it running?".

The /server_services paths are blocked for public visitors by nginx (~/odoo20/nginx/odoo.conf). Requests without the right token get a 403.

Setup after installing

  1. Token. Installing the module creates the system parameter jto_server_services.checker_token (Settings → Technical → System Parameters). Copy its value into a file next to the scripts, readable only by you: 
    cd ~/odoo20/server-services-checker
nano token          # paste the value, save
chmod 600 token
  2. Cron jobs. Run crontab -e and add both lines. Each line has five time fields before the command. If one * goes missing, crontab rejects the whole file (it asks "Do you want to retry the same edit?": answer y and fix it). 
    # Status check (Up / Down) every 2 minutes
*/2 * * * * /usr/bin/python3 -I /home/brownie/odoo20/server-services-checker/check_services.py >> /home/brownie/odoo20/server-services-checker/errors.log 2>&1

# Turn on / Turn off agent: started every minute, flock keeps it to one copy (restarts it if it dies or after a reboot)
* * * * * /usr/bin/flock -n /home/brownie/odoo20/server-services-checker/.control.lock /usr/bin/python3 -I /home/brownie/odoo20/server-services-checker/service_control.py >> /home/brownie/odoo20/server-services-checker/errors.log 2>&1
    Check that both lines are saved, and that the agent starts within a minute: 
    crontab -l
pgrep -af service_control
  3. System services (optional). Docker containers work without this, because your user is in the docker group. Starting or stopping a systemd unit (Jellyfin, CUPS...) needs a sudoers rule, and that rule is also the list of units you allow. Run sudo visudo -f /etc/sudoers.d/server-services and add one line with only the units you want: 
    brownie ALL=(root) NOPASSWD: /usr/bin/systemctl start jellyfin.service, /usr/bin/systemctl stop jellyfin.service, /usr/bin/systemctl start cups.service, /usr/bin/systemctl stop cups.service
    Without it, the button shows "no sudoers rule allows 'systemctl start ...'". Leaving ssh.service out is safer, so you can't lock yourself out of the server.
  4. Test it. Run the agent by hand with -v to see what it does (stop it with Ctrl+C): 
    python3 -I ~/odoo20/server-services-checker/check_services.py -v
python3 -I ~/odoo20/server-services-checker/service_control.py -v
    Errors from both scripts go to ~/odoo20/server-services-checker/errors.log.

Turn on / Turn off rules

  • Buttons only show for services whose Runs as is Docker or System service and that have a Container / unit (comma-separated names).
  • This Odoo is never turned off from Odoo itself. The containers odoo20-odoo-1, odoo20-db-1 and odoo20-nginx-1 are skipped both in Odoo and in the agent. A service that only uses them (Odoo backend, Odoo website) gets no buttons. For the joeltovar.com service, the buttons only stop or start the Cloudflare tunnel.
  • Order: Turn off stops the containers in the listed order. Turn on starts them in reverse order, so list dependencies (databases, VPN) last: e.g. qbittorrent, gluetun. Before starting the next one, the agent waits (up to 90 s) until a container with a health check is healthy, because docker start ignores compose's depends_on. Otherwise qBittorrent starts before the VPN tunnel exists and DHT never connects.
  • Services that share a container (e.g. Immich and Immich public) turn on and off together.
  • A container has to exist (created once with docker compose up -d). docker start can't bring back a container removed with docker compose down.

Troubleshooting

You seeFix
"Still working on it" or "the control agent didn't answer" service_control.py isn't running. Check crontab -l (five fields), pgrep -af service_control and errors.log, then click again.
Every Status stays Unknown check_services.py isn't running or gets 403: check the cron line and the token file.
Power Unknown The agent hasn't reported yet, or a name in Container / unit doesn't exist (check docker ps -a).
"no sudoers rule allows ..." Add that unit to /etc/sudoers.d/server-services (step 3).

Passwords are stored in the database only, never in this module's data: the repository is public.
